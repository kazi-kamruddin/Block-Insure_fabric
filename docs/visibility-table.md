# Dev-lite 1.9.0 field visibility

This source review covers the LevelDB dev-lite medical workflow on
`insurance-dev-lite-190`. Fabric channel members with peer ledger access can
inspect public state and committed transaction history. Browser-facing role
checks constrain Gateway responses. Collection members can have peer access
to private values even when their Gateway accounts cannot request them.

| Placement | Peers that can hold the field | Policy |
| --- | --- | --- |
| Public | All five business MSPs on the channel | Values can appear in public world state, blocks and history. |
| Oracle PDC | HospitalMSP, InsurerMSP and OracleMSP | `oracleProofPrivateData` uses two eligible endorsers and requires dissemination to two peers. BankMSP and AuditorMSP have no collection values. |
| Bank PDC | BankMSP and InsurerMSP | `bankInsurerPrivateData` requires both Bank and Insurer endorsers and dissemination to one peer. |
| Auditor PDC (R2 candidate) | AuditorMSP and InsurerMSP | `auditorReviewPrivateData` requires both endorsements and dissemination to one peer. Exact transient facts are checked against the original Oracle PDC hash. |
| Gateway or client | Role-controlled server response, restricted local storage or a user's browser | Access depends on the route and the local custody configuration. |

Each collection has member-only read and write enabled. Private writes still
leave public hashes. Hospital identities share one HospitalMSP, so a
hospital-scoped Gateway response does not provide cryptographic separation
between facilities. Moving fields in a later release leaves historical
blocks, events and dossier exports intact. [Collection configuration](../network/config/collections_config.json)

**Gateway reader abbreviations**: **I** is insurerAdmin, **C** is the
owning policyholder, **H** is the relevant hospital officer, **A** is an
auditor with a current assigned medical review, and **B** is the Bank
officer. **W** is a server-side Oracle worker using the registry bearer
credential. Auditors read medical private fact projections through the
Insurer Gateway after a claim assignment check. The four reviewers and all
three Oracle subjects are separate accounts in their respective shared MSPs.

## Public Claim

All 40 fields are peer-public. I, C and A can read the applicable claim
through scoped Gateway responses. B gets the current payout projection with
claim ID, claim version, certificate hash and path, and settlement fields
through the Bank route. H gets related hospital assets through hospital
routes. Full claim fields remain visible to channel peers. The read
dependencies below refer to chaincode evaluation or
transaction behavior. [Claim definition](../chaincode/insurance-contract/src/types.go#L288)

## R2 decision

Prototype minimisation only after testing the whole payout and adjudication
dependency chain. A release timestamp and private cover receipt are narrower
initial candidates. The stable association and episode links, exact payout
and incident date require replacement checks across Auditor, Bank or
Oracle paths. Include ordinary proposal arguments, emitted events and
public copies in the review. If compatibility and endorsement cannot be
shown, retain current state and record the privacy limitation.
